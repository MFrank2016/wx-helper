# BGA 接口文档与 SDK 设计

日期：2026-10-16
状态：待用户确认
待落地位置：`plugins/bga_plugin/docs/bga-sdk-design.md`

---

## 1. 意图与目的

上一轮已经做出一个能用的 BGA 查询插件。这一轮的诉求是把底子打扎实：

1. **一份详细、可照着调的 BGA 接口文档**——覆盖 BGA 主站（非游戏内）的数据接口。
2. **一个 SDK**——把 BGA 的操作封装成可复用的包，插件改为调用它，以后加功能不用再摸接口细节。

## 2. 已确认的前提（本轮开工前已定）

| 项 | 决定 |
|---|---|
| 文档边界 | 主站全覆盖：整理全部接口；游戏内实时对局接口另开一节并明确标注未穷尽 |
| SDK 范围 | 只读接口 + **账号自助类**写操作（改资料、加好友/处理好友请求、标记消息与通知已读、收藏与关注游戏） |
| SDK 位置 | 现有 `plugins/bga_plugin/` 仓库内，作为独立包 |
| 凭据 | 存插件目录下本地配置文件，不入任何仓库（沿用现状） |

## 3. 已有素材（本轮的研究产出）

对 BGA 自己发布的前端 JS 做了系统性提取（匿名抓取 14 个入口页 → 下载其引用的 4 个 JS 包 → 提取所有接口调用点），得到：

- **接口调用点记录 669 条，去重路径 578 个，74 个模块。**
- 其中判定为「返回 JSON 的数据接口」的约 551 个（其余是页面链接或未能确认）。
- 每条记录含：路径、参数键名（含字面量默认值）、来源文件、代码片段、功能上下文（启发式）。
- 原始清单：`bga_endpoints_raw.md`（429 KB）/ `bga_endpoints_raw.json`（580 KB）。

抽检与实测对照完全一致（`getPlayerInfos`→`id`、`getArenaRankingAroundPlayer`→`player/game/season`、`getRanking`→`game/start/mode`、`seeMorePrestige`→`start`、`loginUserWithPassword`→`username/password/request_token`、`getGameInfosById`→`gameId`）。

**这份素材的已知边界（写进文档，不能掩盖）：**
- **未覆盖游戏内（`/table`）**：桌页专用包未解析，`gamepanel` 与桌内动态接口不完整。
- 未覆盖 `studio.boardgamearena.com`、各具体游戏的包。
- 12 条路径由拼接构造，参数未知；约 57 条第二参数是变量，参数键名缺失。
- 参数只取对象字面量第一层键，嵌套与数组未展开。
- `context` 字段是启发式，minified 下会退化，**不可当事实**。
- 全部为**静态**结果：未运行页面，未验证可用性与返回结构。

## 4. 交付物

### 4.1 接口文档 `plugins/bga_plugin/docs/bga-api.md`（重写扩充）

结构：

1. **通用约定**：域名与语言子域、会话引导、`requestToken` 双形态、请求头、统一返回格式与错误码、登录流程、限速与合规口径。
2. **按功能域分节**（12 个域）：账号与登录、玩家资料与搜索、排行榜与赛季、桌游列表与信息、大厅与对局概览、好友与社群、消息与通知、收藏与关注、统计、新闻与论坛（只列不封装）、管理类（只列不封装）、游戏内实时对局（标注未穷尽）。
3. 每个接口给出：**路径 / 方法 / 参数（名称+含义+必填+示例）/ 是否需要登录 / 返回结构 / 实测状态 / 备注**。
   实测状态分三档，逐条标注：`✅ 实测`（本轮或上一轮真实调用过）/ `📄 静态`（仅从 BGA 前端包提取，未调用）/ `❓ 待定`（参数或用途不确定）。
4. **附录 A**：全量 578 条清单（按模块），逐条标注上述状态。
5. **附录 B**：未覆盖范围与已知不确定项。

**本轮实测计划**：以「覆盖 SDK 将**具名封装**的全部接口」为先，**不设数量上限**（预计 40–80 个）；不为未具名封装的接口硬凑实测，也不为凑数去调全部 578 个。

优先通道是 **SDK 自己的会话**（即用户把 BGA 账号密码填进 `bga_config.json`）——这样实测同时覆盖 SDK 的传输层与登录链路；**登录态浏览器作为备用通道**。附录 A 会逐条标明哪些只有静态依据。

### 4.2 SDK `plugins/bga_plugin/bga_sdk/`

```
bga_sdk/
  __init__.py          # 导出 BGAClient、模型、异常
  errors.py            # BGAError / SessionError / AuthError / WriteNotAllowed / APIError
  session.py           # 会话引导、登录、requestToken 双形态、限速、806 自愈（由现有 bga/session.py 提升并加固）
  transport.py         # 底层请求与统一错误映射
  models.py            # dataclass：Player / RankingRow / ArenaEntry / GameInfo / SeasonInfo / FriendEntry ...
  endpoints.py         # 接口路径常量（按域分组）
  api/
    account.py         # 登录、登出、账号信息、改资料
    player.py          # 玩家资料、搜索、世界排名
    ranking.py         # 总榜、赛季榜、竞技场周边
    games.py           # 游戏列表、游戏信息、短名↔ID
    collection.py      # 收藏 / 关注（读 + 写）
    friends.py         # 好友列表、加好友、处理好友请求（读 + 写）
    messages.py        # 消息与通知读取、标记已读（读 + 写）
```

**两层 API**：

- **通用层**：`client.call(path, params=None, *, method="POST")` —— 用于调用文档里**静态路径完整**的接口（约 540 条），包括 SDK 未具名封装的。这满足「都封装」的诉求，且不强迫为 578 个接口各写一个包装（大量接口未实测，包装出来也是空壳）。
  通用层**覆盖不了**清单里的三类记录，文档与附录 A 会逐条标注为「通用层不可直接调用」：路径含 `${...}` 模板或 `|` 二选一（需调用方自行补齐段）、带 `?` 查询串、以及参数未能解析出来的。
- **具名层**：对已实测、确实有用的接口提供具名方法与返回模型。

**写操作的安全设计**（重要）：

**放行白名单（能力级；最终路径在实现时按原始清单逐条落定）：**

1. **标记已读**：留言板留言已读、新闻已读、提示气泡已读。（原始清单里**不存在**「私聊消息标记已读」接口，此项已按清单收窄。）
2. **收藏与关注**：收藏／取消收藏游戏、加入想玩清单。（**不含**「求局／匹配」类接口——那属于对局范畴。）
3. **改资料**：性别、生日、国家、城市、简介、头像色、语言、时区、音效等展示类字段。
4. **好友**：添加好友、接受／拒绝／取消好友请求。（**不含**删除已有好友。）

**明确排除：** 改邮箱、改用户名、改密码、删除好友、举报／屏蔽、论坛发言、一切对局类操作、一切管理类操作。

**门禁机制：**

- SDK 默认 `allow_write=False`；所有写方法在未开启时抛 `WriteNotAllowed`，**不发任何请求**。
- 写操作**只能走具名方法**；具名方法内部校验目标路径在 `WRITE_ALLOWLIST` 内，不在即抛错。
- 通用层 `call()` 默认是**只读语义**，它**不**尝试自动判定读写（原始清单里根本没有读写标记，靠猜会出错）。调用方若显式传 `write=True`，同样必须通过 `WRITE_ALLOWLIST` 校验——这样即使有人误用通用层，也动不到白名单外的写接口。
- 每个写方法在文档与 docstring 里写明它改了什么、是否可逆。

### 4.3 插件改为调用 SDK

`plugins/bga_plugin/bga/` 现有的 `session.py` / `client.py` 改为薄适配层，内部委托给 `bga_sdk`；`commands.py` / `store.py` / `snapshot.py` 的对外行为**保持不变**。命令行为、缓存 5 分钟、绑定唯一、趋势口径等已确认的业务规则不得改变。

## 5. 非目标（不做）

- 不做游戏内对局操作（建房、加入、出牌、桌内聊天）——需要桌页专用包（本轮未解析），且风险最高。
- 不做公开发言类写操作（论坛发帖/回复）。
- 不做 BGA Studio、不做具体游戏包。
- 不做多账号、代理池、验证码或反爬绕过。
- 不为 578 个接口逐个实测或逐个写具名包装。
- 不修改 `wxbot_framework/` 框架代码。

## 6. 约束

| 约束 | 来源 |
|---|---|
| 微信正文 1–1023 UTF-8 字节 | 框架 `sdk.py`，仅影响插件渲染，不影响 SDK |
| 插件回调在独立线程串行执行 | 框架 `plugins.py` |
| 只用 Python 标准库，不新增依赖 | 既有约定 |
| 请求基址 `https://en.boardgamearena.com` | 上一轮实测 |
| **不请求 `/player`、`/playerstat` 页面路径**；按用户 2026-10-16 的知情决定，调用 `/player/player/*.html` 数据接口 | 上一轮决定 |
| 写操作会作用于用户真实 BGA 账号 | 因此默认关闭 + 白名单 |

## 7. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 写操作改到用户账号上的真实数据 | 用户资产/声誉 | 默认关闭、白名单、文档写明、不做公开发言类与对局类 |
| 578 个接口绝大多数未实测 | 文档里的参数/返回可能不准 | 逐条标注 `📄 静态`；只对封装进 SDK 的接口做真机实测 |
| 静态提取的 `context` 是启发式 | 误导读者的功能归属 | 文档不使用该字段作为事实，只按路径模块名归类 |
| 内部接口无官方承诺 | 随时可能变 | SDK 集中于 `endpoints.py` 与各 api 模块，便于集中修改 |
| 插件改造引入回归 | 已确认的业务规则被破坏 | 插件对外行为不变 + 第三方业务规则核对 |

## 8. 验证策略（最小）

1. **接口实测**：用登录态浏览器对抽样清单（约 40–60 个）真机调用，记录参数与返回结构；失败或与静态不符的，如实记入文档。
2. **写操作安全**：核对「默认关闭时写方法不发请求」「白名单外的写路径被拒绝」「白名单内的写路径确实会发出请求」——用打桩拦截请求核对，**不对真实账号执行任何写操作**。
3. **插件不回退**：`py main.py --check` 通过；用打桩复现上一轮已确认的行为（排行榜按群取游戏、缓存 300 秒、绑定唯一、趋势 7 个自然日、不请求页面路径）。
4. **业务规则核对**：改造后交第三方核对上一轮那 7 条规则是否仍然落实。
5. 不扩张为回归测试、覆盖率或代码审查。
